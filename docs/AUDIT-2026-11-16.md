## 三、第二轮已修复（约 60 项）

### 3.1 核心 IO / 加密 / 打包
- 临时文件清理加「只删 1 小时前」时间窗，避免冷启动清理误删正在写的容器。
- `fullSyncDatabase` 改为按分类读旧索引行、用 COUNT 判空，显著降低峰值内存。
- `releaseBuffer(secure)`：只有容器/密码路径擦除，哈希/复制等高频路径不再整块 1MB 清零；加密路径显式 `secure = true`。
- 分卷导出失败回滚已入库分卷（文件 + DB 行）；删掉每个 URI 多余的 `getFileName` 查询。
- 递归压缩包超深不再静默：计入失败并上报；顶层导入异常回填 `failedCount`。
- EPUB：属性匹配加边界校验（不再命中属性值里的同名子串）；条目读取改限长流式（32MB），未知大小也受控。
- 指纹缓存：临时名随机化（并发写不再互删）；失败只删 tmp，绝不删掉原本有效的缓存。
- 完整性抽查：加互斥锁串行化（cursor/total_bad 读-改-写不再互相覆盖）；去掉两次整表复制；读取失败计入 `skipped` 而非「损坏」；`last_run` 同步落盘、游标 `apply`。
- 查重哈希回写改批量（500/批 `upsertAllLocked`）；完整性进度按 1%/200ms 节流。
- 新增 `PjmDispatchers.Decode`（`Default.limitedParallelism(3)`），图片解码不再占满 8 线程 IO 池。
- **加密热路径**：`write(int)`/`read()` 复用单字节缓冲（不再逐字节分配）；单字节走 Kotlin 快路径（不再一次 JNI 往返）；批量改 `GetPrimitiveArrayCritical`（省两次 1MB 级拷贝）。
- 缩略图/指纹孤儿清理跳过 `.tmp` 临时文件（不会再删掉并发写入中的文件）。

## 四、仍未改动 / 有意保留（含原因）

1. **旧版 PJM-Link 会被 401 拒绝**：令牌鉴权已上线，旧电脑端必须更新到本版附带的脚本；已用 401 + `upgrade:1` 给出明确提示，不做静默降级。
2. **PC 端 PowerShell 服务并发**：`PJM-Link.ps1` 监听循环单线程，上传期间 `state` 会排队；手机端已用「推送期间暂停轮询」缓解。改 PS1 并发模型回归风险高，本轮不动。
3. **`fullSyncDatabase` 逐分类替换的原子性**：索引重建现在是「按分类多个短事务」，中途被杀会出现「部分分类是新数据、部分还是旧数据」的混合态（下次全量同步会自愈，不会丢文件）；彻底原子化需要单事务写入全部行，代价是峰值内存与长事务锁，本轮按可恢复性取了折中。
4. **发现页窗口只能向尾部裁剪**：`computeWindow` 只裁远离当前页的远端，向后翻超过约 100 页即无法回退（懒加载补历史需要一次全量重排）；视频持续播放期间窗口不裁剪（`canTrim` 为 false），长时间连播内存仍会缓慢增长。
5. **发现页 pump 全量查询 / 首页封面一次批量取图 / 音频名按路径记录**：均需 data 层新增接口（DAO LIMIT、批量封面、回填跳过集合）；本轮只在现有接口内收敛（查询次数/时间窗/缓存快路径）。
6. **热力图直方图**：UI 侧改为 200 样本上限，极端分布可能轻微失真；精确分桶需 SQL 聚合接口。
7. **AIDL 固定 token 与 API 24–29 共享目录可写**：协议级随机令牌需要客户端与服务端同时改并考虑 shell 进程读不到应用私有目录；本轮只做了 NUL 分隔、原子写、超时清理等加固。
8. **`ShareUtils` 批量 Uri 1MB 事务上限**：大批量分享仍有 `TransactionTooLargeException` 风险，已注释标注；正确做法是超限打包分享（改变交互）。
9. **`AppDatabase` 迁移表从 9→10 起**：v8 及更早的在网数据库仍会 fail-fast；已确认无此版本存量用户，不再补迁移。
10. **`Configuration.screenWidthDp` → `LocalWindowInfo.containerSize`**（lint 建议）：阅读器排版尺寸口径，改动需回归分屏/旋转。
11. **整卡可点区域的语义合并**：文件卡片目前是「图标按钮有描述 + 卡片本身 onClick」，读屏会连读两次；合并成单一语义节点需要重排点击层，收益小于回归风险。
12. **文件浏览器路径显示名**仍在组合期查询 `DocumentFile.name`（仅标题栏一处，收益小）。
13. **接管任务 `createdAt` 语义**：已用于失败态过期清理；`@Upsert` 重建整行仍可能刷新时间戳（影响范围已缩小）。

## 五、建议的后续优先级

1. **PC 端（8788 服务）也加鉴权**：手机回环端口已有令牌，但电脑侧监听仍无校验，同一局域网内其他机器可直接连——下一版优先补。
2. **`PJM-Link.ps1` 并发模型**：改成多线程/异步监听，上传期间 `state` 不再排队，手机端就能恢复实时轮询（当前推送时暂停轮询是权宜之计）。
3. **发现页向历史方向懒加载**：需要一次全量重排 + 索引重映射，配合窗口裁剪后可以做到「无限回退且内存有界」。
4. **`ShareUtils` 超限打包分享**：超过 Uri 事务上限时自动改成「打包成一个 zip 分享」，把 `TransactionTooLargeException` 从根上去掉。
5. **`LocalWindowInfo.containerSize` 与整卡语义合并**：两处 lint/无障碍遗留，改动面小但需要真机回归。
