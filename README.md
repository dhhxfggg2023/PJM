## 这是什么

PJM 是一个 Android 本地文件保险库应用。它把图片、视频、音频、压缩包等文件收进应用的私有目录统一管理，支持分类浏览、批量操作、内容去重，并能以自定义的 `.pjm` 容器格式打包文件用于对外分享。

**它解决的问题**：把散落在各处（尤其是 `Android/data` 等受限目录）的媒体文件集中到一处管理，并在需要发给别人时换成一种不会被社交平台自动审核识别的字节序列。

**它不解决的问题**：它不是加密软件。详见下方 [安全模型](#安全模型必读)。

## 安全模型（必读）

这是使用本项目前**最需要理解**的一节。

### `.pjm` 容器是「混淆」，不是「加密」

`.pjm` 的字节变换采用**固定密钥的异或（XOR）**，密钥硬编码在应用源码里。它的设计目标是：

| 目标 | 是否达成 |
|---|---|
| 让文件的字节序列不再匹配平台的内容哈希库 | ✅ 达成 |
| 让平台的图像/视频分类器无法直接从字节中提取内容 | ✅ 达成 |
| 防止他人查看文件内容 | ❌ **完全无效** |

**固定密钥异或属于「重复密钥异或」（维吉尼亚密码一类），在密码学上早已被攻破**：

- 容器内部是标准 ZIP，含有大量**已知明文**（`PK\x03\x04` 头、结尾的中央目录、成片的 `0x00` 字段）。把已知明文与密文异或即可还原密钥流，进而解开整个文件。
- 因此**密钥再长也没用** —— 攻击者不会去暴力枚举，而会走已知明文这条路。
- 密钥就写在源码里，任何人拿到应用或源码都能直接解密。

**结论**：`.pjm` 挡得住机器，挡不住人。**不要用它保护任何真正机密的数据。** 需要真加密请用成熟的加密工具（AES-256 等）。

### 容器格式版本沿革（诚实记录）

| 版本 | 布局 | 密钥流取字节方式 | 说明 |
|---|---|---|---|
| 无版本字节 | `magic(4)` + ZIP | `pos & 33` | 历史格式。**有缺陷**：`33` 不是 2 的幂，`x & 33` 并不等于 `x % 34`，导致 34 字节密钥中只有 3 个不同字符真正参与运算，密钥强度被削到 3 字节 |
| `0x02` | `magic(4)` + `ver(1)` + ZIP | `pos & 33` | 仅预留，从未实际产出 |
| `0x03` | `magic(4)` + `ver(1)` + ZIP | `pos % 34` | **当前格式**。34 个密钥字节全部参与 |

读端**同时兼容全部历史版本**（按容器自带的版本字节/魔数自动判别），历史容器不会失效。

> ⚠️ 但请注意：**`0x03` 容器无法被 v1.9.3 及更早的版本打开**（算法已不同）。升级不会丢数据（老容器在新版里照样能解），但把新容器发给使用老版本的人，对方打不开。
>
> 另外，修正 `pos & 33` 只是让密钥从 3 字节变回 34 字节 —— **重复密钥异或本身的缺陷依然存在**，不要误以为它因此变得安全了。

### 其他安全相关事实

- 保险库里的文件**以明文存放在应用私有目录**（`/data/user/0/com.dhhxfggg.pjm/files/pjm_vault/`）。只有 `.pjm` 容器经过变换。应用私有目录由 Android 沙箱保护，但 root、可调试包（debuggable）或备份都可以读到。
- `allowBackup` 已关闭，且备份规则排除了保险库目录，避免系统云备份把明文带走。
- 仓库不包含任何密钥、签名文件或令牌（`local.properties`、`*.keystore`、`*.jks` 已被 `.gitignore` 排除）。
- 「传输到电脑」的回环服务（`127.0.0.1:8787`）每次开启都会生成一个随机令牌，写在 `/sdcard/Android/data/com.dhhxfggg.pjm/files/pjm_transfer_token`；数据接口必须带 `X-PJM-Token`，否则返回 401。所以**用浏览器直接访问要手动带上 `?token=<该文件内容>`**，电脑端脚本会自动读取。该令牌只防同机其他应用误连，不是加密：能读应用外部私有目录的进程同样能拿到它。
- 更新检查会校验下载地址的域名白名单，并比对 APK 签名与已安装版本一致，防止中间人替换安装包。debug 与 release 使用**两套独立证书**：debug 用工具链自动生成的调试证书，release 用 `keystore.properties` 指向的正式证书；release 缺配置时构建直接失败，不会回退 debug 签名。CI 用一次性临时证书构建 release 只为验证链路，其产物不要作为正式发布版分发。

## 功能

### 保险库与容器
- **`.pjm` 容器**：文件打包为 ZIP 后经流式字节变换，支持大于 2GB 的文件（64 位偏移）。
- **分卷**：`.pjm.N` 多卷格式，每一卷都是独立完整的容器，可单独解开、互不依赖。
- **原生加速**：核心字节变换由 C++（JNI）实现，采用密钥流铺块 + 64 位整字异或；原生库不可用时自动回退到等价的 Kotlin 实现。
- **原子写入**：容器先写临时文件，`fsync` 落盘后再原子改名；断电或进程被杀不会产生「看起来完整但解不开」的半成品。
- **一键分享**：多选图片/视频打包为容器后直接调起系统分享，MIME 由真实内容推断。

### 资产管理
- **分类**：图片 / 视频 / 音频 / B站视频 / `.pjm` 容器 / 其他。
- **导入**：接收系统 `SEND` / `VIEW` 意图直接入库；支持 zip/rar/7z 压缩包自动解包；B站视频可从用户授权的任意目录（`ACTION_OPEN_DOCUMENT_TREE`）批量导入。
- **浏览**：按日期分桶、搜索、批量选择、系统工具打开。
- **导出**：通过 MediaStore 将单个文件导出到公共目录（`Pictures` / `Movies`），也可调起系统删除请求。
- **缩略图**：图片采样缩略与视频关键帧抽取，落盘为持久缓存，启动时后台补齐缺失项。
- **内容去重**：
  - **精确查重**：按文件大小分组后做内容哈希，字节级一致才归组；
  - **相似图片查重**：dHash 感知哈希粗筛 → 宽高比/面积预过滤 → 32×32 灰度预筛 → 64 宽灰度像素验证，四级过滤后在内存中完成判定；
  - 视频使用「时长 + 分辨率 + 关键帧 dHash」的感知指纹，能识别同源重封装。
- **完整性检查**：区分「文件丢失」与「内容损坏」，损坏判定只对确定是内容哈希的记录生效（感知指纹不参与，避免误报）。

### 阅读器
- **格式**：TXT、EPUB（OPF + spine + 自带目录与封面）、FB2、HTML/XHTML、Markdown，全部本地解析，不联网。
- **编码识别**：先看 BOM，再按字节规律判 UTF-16（有无 BOM 都能认），最后用 UTF-8 / GB18030 两个候选择优——中文 GBK 老书不会整本乱码。
- **章节**：「第 X 章 / Chapter N / 序章 / 楔子 / 番外」等强特征优先，识别失败才用短标题兜底；正文里以「第二章」开头的句子不会被误判。卷/部一级在目录里缩进。
- **翻页**：点屏幕左右三分之一翻页、中间唤出工具条、音量键翻页；顶栏显示书名与当前章节，底部「上一章 / 下一章」。
- **排版**：字号 / 行高 / 左右边距 / 六套配色实时生效；分页结果按「文件 + 排版参数 + 视口尺寸」缓存，换回原设置时瞬间出页。
- **书签**：按段落定位而不是页码，换字号后书签依然落在原处。

### 发现页
- 图片全屏缩放（双击 / 双指），视频播放（拖动快进快退）。
- ExoPlayer 实例池化复用，避免滚动时反复创建解码器。
- 全量打乱队列，一轮内不重复；已看过的会被排除，看完一整轮才重新洗牌（快速划过、未停稳的页不会被计为「看过」）。

### 受限目录与特权访问
- **Shizuku**：以 shell 身份访问 `Android/data` 等受保护目录。
- **内置特权文件服务**：嵌入式 shell 进程（文件队列协议），配合 `start.sh` 可在不安装 Shizuku 的情况下通过 adb 启动；Shizuku 通道则走 AIDL。
  - 服务只接受 `/storage/emulated/0` 内的路径，`copy` 只能落到应用自己的外部私有目录；`/data`、`/system` 等一律拒绝。固定 token 主要防误触发；在 Android 10 及以下共享目录可被其他应用写入的场景，路径白名单把可利用面限制在共享存储内。

### 备份已安装应用
- **提取安装包**：设置 → 备份已安装应用，列出已安装应用（图标/名称/包名/版本/APK 大小），可搜索、可多选。
- **安装包**：提取应用的 APK，命名 `应用名_版本.apk`，一个应用一份文件。
- **入库**：统一存进保险库「其他」分类，与库内其它文件同样可查看、分享、导出；单个应用失败不影响整批。

### 传到电脑 / 从电脑取回
- **全程走 USB**：传输服务只监听 `127.0.0.1`，电脑端经 `adb forward/reverse` 隧道接入；不联网、不耗移动数据，手机上也不产生第二份副本。
- **发到电脑**：按入库日期挑要传的天数（按月份翻页），逐文件推送，进度/速度/平均速度都在手机上算；已传过的文件按 uuid 记账自动跳过。
- **从电脑取回**：先选分类（图片/视频/B站/音频/文本/容器/其他），再按月份翻页选日期，支持整月全选；传输中可随时「停止」，当前文件中途即断，已导好的保留、不残留半截文件。
- **失败可见**：本批失败的文件列在「失败文件」弹窗里，图片/视频带缩略图，文本类显示文件名 + 原因。
- **日期沿用**：取回的文件按电脑上那个日期目录入库，不会把历史文件全算成「今天」，热力图与统计不失真。

### 应用接管
- 指定应用「保存到手机/相册」的新文件自动搬进保险库（先入库，再删原文件），只处理开启之后新产生的文件。
- 后台运行状态一目了然：电池优化白名单、上次扫描时间、后台断档次数；可直接跳到系统的电池/自启动设置页。

### 其他
- 前台服务执行后台任务（带进度通知；取消在文件边界生效；Android 15 超时会释放任务槽位）。
- 冷启动清理孤儿缓存、残留临时文件与失效的浏览历史。
- 内置 **Baseline Profile**：装完即 AOT 编译，首屏与滚动不需要等系统用几天热身。

## 构建

**环境要求**：JDK 17 或更高、Android SDK（compileSdk 37）、NDK 28.x、CMake 3.22+。

刚克隆下来还需要三步，否则第一条报错会让你以为代码有问题：

1. **指明 SDK 位置**。在项目根目录建一个 `local.properties`（已被 `.gitignore` 排除，不会误提交）：

   ```properties
   sdk.dir=D\:\\Android\\Sdk
   ```

   或者设环境变量 `ANDROID_HOME`。两者都没有时的报错是 `SDK location not found`。

2. **手动装 NDK 与 CMake**（AGP 不会自动下载，缺了会在配置阶段失败）：

   ```bash
   sdkmanager --licenses
   sdkmanager "platforms;android-37.0" "build-tools;36.1.0" "ndk;28.2.13676358" "cmake;3.22.1"
   ```

   注意平台包名带次版本号（`android-37.0`，不是 `android-37`），装错名会直接报错退出。CI 用的是同一组包名，见 `.github/workflows/ci.yml`。

3. **debug 直接构建**，不需要任何密钥：调试签名由 Android Studio / 工具链自动生成（`~/.android/debug.keystore`）。

   **release 必须先配好正式签名**：debug 与 release 用两套独立证书，release 缺配置时构建直接失败（不会回退 debug 签名）。在项目根目录放一个 `keystore.properties`（已被 `.gitignore` 排除）：

   ```properties
   storeFile=/path/to/pjm-release.jks   # 绝对路径，或相对项目根目录
   storePassword=...
   keyAlias=pjm
   keyPassword=...
   ```

   **请务必离线备份证书与密码**：丢了就无法覆盖安装，只能卸载重装（应用数据会一起丢）。证书本体与密码应当存放在**仓库之外**的可信介质上（U 盘、加密盘或密码管理器），并在那里另记一份 SHA-256 指纹与有效期备查。CI 用一次性临时证书构建 release 只为验证链路，产物不可分发。

```bash
./gradlew :app:assembleDebug      # 调试包
./gradlew :app:assembleRelease    # 发布包
```

**维护者注意**：不要提交 `systemProp.gradle.user.home`（Windows 绝对路径会让 Linux/macOS 的构建在项目根建出 `D:` 目录），也不要提交 `gradle/gradle-daemon-jvm.properties` 里的 `toolchainVersion`（它把 Gradle 守护进程钉死到某个 JDK，别人机器上没有时 Gradle 会去 foojay 下载整个 JDK，下不到就直接构建失败）。需要自定义 Gradle 缓存位置时用环境变量 `GRADLE_USER_HOME`。

常用任务：

```bash
./gradlew :app:testDebugUnitTest  # 单元测试
./gradlew ktlintCheck             # 代码风格检查
```

**运行要求**：Android 7.0+（minSdk 24），targetSdk 35。需要存储权限；Android 11+ 的「所有文件访问」是可选的（不授予也能使用本地保险库，仅影响 `Android/data` 访问），也可用 Shizuku 替代。

## 数据迁移与备份

应用内**不再提供备份功能**：原「整库导出为 PJM 分卷」与「数据库每日备份」已删除。
两者都会在手机本地再存一份完整副本，而全库体量往往远超手机剩余空间，无法承担这个翻倍开销。

后续计划改为**直接文件传输**（手机与电脑点对点搬运），而不是「先在手机里打包一份、再把产物传出去」。

保险库位于应用私有目录 `/data/user/0/com.dhhxfggg.pjm/files/pjm_vault/`，其中普通文件是**明文**（只有 `.pjm` 容器经过变换）。系统云备份与设备迁移已被排除在这些目录之外。极端情况下需要取回数据时，可安装可调试包后用 `adb shell run-as com.dhhxfggg.pjm ...` 手动读取；取回的内容同样是明文，请存放在可信介质上。

## 已知限制

- **不是加密软件**，见 [安全模型](#安全模型必读)。
- **应用内没有备份/恢复/迁移功能**（见上），整库搬运只能借助电脑 + adb 手动处理。
- **`0x03` 容器与 v1.9.3 及更早版本不兼容**（新包发不出去给老版本用户）。
- 相似图片查重采用 4×16 位分块倒排索引粗筛（替代 O(n²) 全量比较，38k 张约 1 亿次定长数组扫描，随数量近似线性）；首次仍需逐张解码生成指纹，之后增量很快。
- 保险库使用**扁平目录**存储（单目录可达数万文件），在十万级规模下目录遍历会变慢。
- 仅在 Android 15（API 35）的真机与模拟器上做过实际验证，其余版本未系统测试。
